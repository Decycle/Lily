# Faithful core-loop rewrite plan

> The original design plan, kept for reference. Some details (crate split, FFmpeg as DLLs) changed during
> implementation; the current state is in the [README](../README.md), open items in [ROADMAP.md](ROADMAP.md).

Native Rust desktop reimplementation of WACCA Reverse (3.07.01) gameplay, built for one touchscreen laptop
(1920×1200, Windows 10), using the original assets in `assets/`. Personal use only — assets never go into git.

Sources: `docs/research/01..06-*.md` (details, citations, and UNVERIFIED markers live there).

## 1. Scope

**In:** title → song select (sort/filter, preview audio, jackets) → difficulty select (Normal/Hard/Expert/Inferno)
→ play options → song play (original look: background video, playfield, hit effects, hit sounds) → results
(score, grade, lamps, judgement counts, fast/late) → save personal bests + rating.

**Out:** multiplayer/co-op, coins/credits/free play, Aime cards and login, servers, bingo, sugoroku/stage maps,
gates, trophies/titles, unlock economy (everything unlocked incl. Inferno), arcade closing time, LEDs, test menu,
character story/MyRoom.

## 3. Architecture

Cargo workspace in this folder:

```
crates/
  wacca-formats   # pure parsers, no IO policy: mer, UE4 package/DataTable/Texture2D/widget, CRI @UTF/ACB/AFS2, USM demux
  wacca-convert   # CLI: assets/ -> data/ (one-time, re-runnable, idempotent)
  wacca-audio     # HCA/ADX decode (cridecoder behind a trait; clHCA port as fallback), mixer, cpal output, audio clock
  wacca-game      # pure deterministic rules: timing, judgement, score, gauge, grades, rating, save model (no GPU/OS)
  wacca-video     # USM demux + MPEG-1 decode -> frames (FFmpeg via dynamically loaded DLL)
  wacca-render    # wgpu: playfield, notes, effects, sprites, text, video quad; WGSL shaders
  wacca-app       # winit window, Windows touch, scenes (title/select/options/play/results), save IO
```

**Runtime data (`data/`, generated by `wacca-convert`, gitignored):**
- `songs.json` (from MusicParameterTable + resolved cue/movie/jacket per difficulty), `rules.json` (Judge/GameScore/ClearRate/Norma/UserRate tables), charts copied as `.mer` (parsed at runtime; tiny)
- textures → PNG atlases; fonts → TTF/OTF copied; widget layouts → JSON
- audio: keep the original `.awb` banks and stream HCA directly (no re-encode, no extra disk); SE bank pre-decoded to WAV at convert time (small)
- video: keep `.usm` (20 GB already on disk); demux at runtime

**Timing model:** the audio output clock is the master. Song time = samples played / 48000 − output latency + user offset.
Judgement is evaluated on input timestamps (not render frames), converted to the game's 60 fps frame units so the
windows are bit-for-bit the table values. Rendering interpolates from audio time every frame (vsync, any refresh rate).

**Input:** native Windows touch (winit touch events / WM_POINTER) → mapped onto a virtual 60×4 sensor ring centred on the
playfield, reproducing the cabinet's sensor layout so the input rules (slide/snap detection, hold) operate on the same
data the real game sees. Mouse/keyboard fallback for testing. Window is portrait 9:16 scaled to screen height.

**Save:** `%APPDATA%\lily\save.json`, versioned; per chart best score / best combo / min miss / counters
(play, clear, missless, FC, AM, per grade); options; atomic write (temp → flush → `.bak` → rename); rating recomputed on load.

## 4. Milestones

Each milestone ends with something runnable and a check against the real game (which runs on this PC via segatools).

| # | Milestone | Done when | Est. |
|---|---|---|---|
| M0 | Toolchain + workspace + CI-style `cargo test` | builds on Windows (GNU toolchain) | ½ day |
| M1 | `wacca-formats`: mer parser + timing; DataTable reader; ACB/AFS2 | all 1,247 charts parse; note counts match published counts (e.g. S01-032: 200/333/692); tables round-trip to JSON identical to research dumps | 3–4 days |
| M2 | Audio: HCA decode + play one song + metronome/clap on chart notes | claps line up with the music by ear (verifies `#OFFSET` direction) | 2–3 days |
| M3 | Minimal playfield: ring, lanes, notes moving outward (flat colours) synced to audio | plays any chart visually; note positions match a side-by-side recording of the real game | 4–6 days |
| M4 | Touch input + full judgement/score/gauge in `wacca-game` (unit-tested) | playable start to finish; results numbers consistent; autoplay produces 1,000,000 / AM | 1–2 weeks |
| M5 | Song select + difficulty + options + results + save (functional UI, simple styling) | full core loop playable; bests persist | 1 week |
| M6 | Faithful visuals: converter for UI textures/fonts/layouts; original note/ring textures; hit effects; judgement sprites; combo font; background video | side-by-side looks like the original playfield | 2–3 weeks |
| M7 | Faithful menus: title, song select, difficulty, options, results using extracted layouts + re-authored animations | menus look like the original | 3–5 weeks |
| M8 | Accuracy pass: verify open questions against the real game/binary | items in §5 resolved or consciously accepted | ongoing |

M0–M5 (~4–5 weeks) gives a complete, playable game with plain visuals; M6–M7 bring the original look.
